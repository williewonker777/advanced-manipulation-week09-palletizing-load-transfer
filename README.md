# Week09 R8 — L2d 검증과 기존 최종 유지

## R8 추가 검증 — 후보 비채택, 기존 최종 유지

C1(서보 R1 제어 + R7 감지 + L2d)은 새 holdout·공식 회귀에서 검출을 늘렸지만 최종 생산 import 검사에서 실패했다. 고치거나 검사를 완화하지 않고 기존 최종(서보 R7·토크 R1)을 유지했다. 이는 L2d 이득 부재가 아니라 조립·제출 검증 실패다.

- 새 holdout은 456 실제 루프·한 배치이며 서보 추가 8/90, 손실·조건별 오감지 증가 0이다. 공식도 방식별 1회 통과했다.
- C1 감사 p99 626.945 µs는 통과했으나 최대 7.992 ms, holdout 1 ms 초과 서보 0→14주기로 최대 1 ms는 미달이다.
- B1 전체 시험을 C1 overlay가 아닌 fallback 경로에서 돌려 import 실패를 늦게 발견했다. 후보를 바꾸지 않았고 fallback 최종 775시험과 제출 계약을 다시 통과했다.
- G4·토크 감지·기존 섭동 오감지·약한 수직 충돌·숨은 조건은 여전히 남는다. 기존 요구사항/평가기 점검/문제별 해결·미흡 표는 아래에 보존했다. 아래 R7 절의 재실행 여부와 시험 수는 당시 기록이다.

## 판정 복원 경위

S5 문서 연결 검사 뒤 R1으로 되돌린 기록은 보존했다. 이후 명시적 사용자 결정 ‘서보 후보 채택 복원’에 따라 A 서보 후보를 최종 제출에 복원했다. protocol의 되돌림 조건과 실행 순서에는 문서 연결 검사가 포함되지 않는다. 후보·자료·관문 숫자는 바꾸지 않았고 시뮬레이션·holdout·공식 평가는 다시 실행하지 않았다. 복원한 최종 조립으로 작업 사본 688개와 공개형 사본 569개 전체 테스트, 각 기본 제출 계약 8개를 새로 통과했다. 기존 677개 기록은 S4 후보 계약의 보존값이며 이번 테스트 수와 합치지 않는다.

## 결론과 근거

A 서보에는 기록 결함을 고친 검증 경로로 확인한 SCALE_STATE 감지 채널을 채택했고, B 토크는 R1을 유지했다. NumPy scalar만 기본 JSON형으로 엄격하게 바꾸고 배열·NaN·무한대·비문자 key는 거부했다. 후보·모델 263개 파라미터·임계값·정규화·R1 제어기·관문 숫자는 바꾸지 않았다. 사전 전체 677개와 최종 전체 677개, 기본 이름 8개 검사가 통과했다. 저장 자료 990개(방식별 495개)의 실제 감지기 출력과 새 조건 8회의 물리 8배열을 dtype·shape·바이트 단위로 비교해 모두 같았다. 상세는 [R7 결과](docs/R7_RESULTS.md), [R7 방법](docs/R7_METHODS.md), [발표 PDF](results/presentation.pdf)에 있다.

## 요구사항 점검

가이드 33개 항목은 24개 충족, 4개 부분 충족, 5개 판정 불가다. 런타임 입력·제출 형식·무결성 8개 검사는 모두 통과했다. 최종 감지 파일이 바뀌어도 허용 입력과 제어기를 바꾸지 않아 이 판정은 유지된다. 상세는 [요구사항 점검](docs/REQUIREMENTS_AUDIT.md)에 있다.

## 평가기 점검과 R1 놓침

원본 평가기는 조건·집계·출력에서 판정을 뒤집는 결함이 확인되지 않았다. R1의 공식 8 kg 놓침 6건은 두 방식에서 집기 1.42 s의 10·15 N, 놓기 3.86 s의 10 N이며, 연속성·그립·정상 분기·임계 조건의 결과다. [평가기 점검과 미검출 원인](docs/R4_README.md#평가기-점검과-미검출-원인)을 함께 본다.

### 3. 해결해야 할 과제

아래는 우선순위별 시도할 방향이며, 효과를 확인하거나 개선을 약속한 결과가 아니다.

1. **하중 이양(G4)**: 놓기 전 지속 지지를 높이는 제어가 필요하다. 먼저 필요한 변위·속도를 식별한다. [토크 추적 feedforward](docs/R4_README.md#이번에-시도하지-않은-것)는 아직 구현하지 않은 시도할 방향이며 효과는 모른다.
2. **약한 집기·놓기 충돌**: 그립·해제 과도와 충돌을 구분하는 구간별 감지가 시도할 방향이다. 현재 진단은 잡음 시드 1개와 고정된 일곱 점수에 한정되며 분리 가능성은 미확정이다. 같은 공식 조건을 다시 독립 검증이라고 부를 수 없다.
3. **최대 1 ms와 계산 비용**: 실행 우선순위·CPU 격리 같은 실시간 실행 환경과 계산 경량화를 함께 검토하고 대상 환경에서 다시 측정해야 한다. 엄격한 시간 상한은 아직 보장하지 못한다.
4. **섭동 오감지**: 관절 강성 변화와 오감지의 관계를 분석하고 정상 자료 범위를 넓히는 것이 시도할 방향이다. 충돌 결과에 맞춘 임계 조정으로 해결을 주장하지 않는다.
5. **토크 감지 개선**: 토크 방식에 맞는 새 특징을 검토한다. 기존 SCALE_STATE의 실패 관문은 그대로 두고 효능·오감지를 다시 검증해야 한다.
6. **서보 포화 2/189**: 해당 조건과 포화 시점을 식별하고 원인을 확인한 뒤 완화 방향을 정한다.
7. **숨은 조건 대비**: 질량·COM·외력 방향을 넓힌 별도 holdout을 사전에 정할 필요가 있다. 비공개 조건 일반화나 안전성을 약속하지 않는다.
8. **선택 항목**: 가이드의 충돌 뒤 정지·후퇴 반응은 구현하지 않았다. [선택 항목과 요구사항](docs/REQUIREMENTS_AUDIT.md)을 구분한다.

유한 시뮬레이션 결과이며 하드웨어 안전 보장이나 충돌 정지 인증이 아니다.
