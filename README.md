## 결론과 근거

S5 공개 문서 연결 검사(고아 문서 10개) 실패로 A 서보와 B 토크 모두 R1을 유지했다. 실패 뒤 후보를 고치거나 다시 실행하지 않았다. NumPy scalar만 기본 JSON형으로 엄격하게 바꾸고 배열·NaN·무한대·비문자 key는 거부했다. 후보·모델 263개 파라미터·임계값·정규화·R1 제어기·관문 숫자는 바꾸지 않았다. 사전 전체 677개와 최종 전체 677개, 기본 이름 8개 검사가 통과했다. 과학·공식·계약 관문은 통과했지만 S5 고아 문서 10개 검사 실패로 최종 R1이다. '저장 자료로 승계한 단계'·'새 holdout'·'새 공식'은 e26 후보 시험 표이며 최종 R1 성능표가 아니다(H의 R1 비교 열은 실제 R1 참조 측정). 새 공식 A 49/37 ms는 후보값이고 최종 R1 보존값은 62/45 ms다. 최종 R1 전체 공식표는 docs/R7_PUBLICATION_VETO.md에 있다. 저장 990스트림은 R6 승계다. 677개/기본 이름 8개는 후보 검사이며 R1 전환 뒤에는 정적 SHA만 확인했다. 상세는 [R7 결과](docs/R7_RESULTS.md), [R7 방법](docs/R7_METHODS.md), [발표 PDF](results/presentation.pdf)에 있다.

## 요구사항 점검

가이드 33개 항목은 24개 충족, 4개 부분 충족, 5개 판정 불가다. 런타임 입력·제출 형식·무결성 8개 검사는 모두 통과했다. 최종 감지 파일이 바뀌어도 허용 입력과 제어기를 바꾸지 않아 이 판정은 유지된다. 상세는 [요구사항 점검](docs/REQUIREMENTS_AUDIT.md)에 있다.

## 평가기 점검과 R1 놓침

원본 평가기는 조건·집계·출력에서 판정을 뒤집는 결함이 확인되지 않았다. R1의 공식 8 kg 놓침 6건은 두 방식에서 집기 1.42 s의 10·15 N, 놓기 3.86 s의 10 N이며, 연속성·그립·정상 분기·임계 조건의 결과다. [평가기 점검과 미검출 원인](docs/R4_README.md#평가기-점검과-미검출-원인)을 함께 본다.

## 미달과 범위

- G4 기준은 마지막 20 ms 평균 ≥50 %mg, 최소 ≥25 %mg, v1 대비 +25 %p, 놓기 힘 ≤1.1 mg다. 현재 A는 평균 0.2098, 최소 0.0000, 증가 0, peak 1.0045; B는 평균 11.1507, 최소 0.3802, 증가 0, peak 1.0140이다.
- 새 holdout 합산 최대 2210.500 µs다. R1 관측 최대 A 11.703 ms, B 14.163 ms와 함께 모든 1 ms 초과 주기를 보존했다.
- 공식 8 kg의 집기 1.42 s 10·15 N과 놓기 3.86 s 10 N에서 현재 미검출은 A 3건, B 3건이다. R1은 두 방식 각 3건, 총 6건이었다.
- 무충돌 섭동 28 reference FA는 A 6→6, B 9→9다.
- D4 R1 A 서보 포화는 2/189다. 후보 채택 여부와 별개로 이 한계를 공개한다.
- 유한 시뮬레이션 결과이며 하드웨어 안전 보장이나 충돌 정지 인증이 아니다.
