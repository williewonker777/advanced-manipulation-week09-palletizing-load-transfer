# R21: 집기·놓기 직전 10 N을 찾은 방법과 남은 경계

**시뮬레이션용 토크 연구 옵션이다. 수업 원본 데모도, 기본 제출본 교체도 아니다.** 제공된 프로그램과 제공 제어기·감지기로 실행한 예제는 [원본 데모 확인법](DEMO_SOURCES.md)을 참고한다. 아래 ‘공식’은 **변경하지 않은 수업 평가기**로 측정한다는 뜻이다. R21의 제어기는 R10이다.

## 같은 공식 평가기에서 토크 감지기만 바꾸면

| 토크 감지/제어 조합 | 구별한 공식 충돌 (전체 24) | 집기 직후 10 N, 0 / 8 kg | 놓기 직전 10 N, 0 / 8 kg |
|---|---:|---|---|
| 수업 기본 제어기 + 기본 감지기 | 11 | — | — |
| R10 제어기 + 기본 제출 감지기 | 18 | 미검출 | 미검출 |
| R10 + R20 수평 잔차 | 20 | 미검출 | 미검출 |
| R10 + 집기 구간 힘 예측 | 22 | 47 / 49 ms | 미검출 |
| R10 + 전 구간 공통 회전 모멘트 한계 | 22 | 미검출 | 88 / 88 ms |
| **R10 + 구간별 회전 모멘트 한계** | **24** | **44 / 43 ms** | **92 / 91 ms** |

원본 행의 ‘—’는 이 표에 상세 지연을 싣지 않았다는 뜻이다. [전체 6개 조합과 제어표](../results/r21/torque_official.json). 선택 옵션에서 무충돌 0·4·8 kg 오경보는 각각 0회다. **모든 실행에서 오경보가 0이었다는 뜻은 아니다.** 충돌이 있는 8 kg·3.0 s 행에서 기존 오경보 최댓값 1회가 남는다. 기본 파일명으로 독립 실행한 결과와 서보 R10 대체 동작은 [검증 기록](../results/r21/standalone_official.json)에 있다.

### 무엇을 측정했나

관절 엔코더와 영점 보정한 스프링 토크로 링크 각도를 추정하고, R10 제어기가 이미 계산한 관성행렬의 첫 행으로 수직 기저축에 대한 각운동량을 구한다. 여기서 구동 토크의 시간 적분을 빼고, 32 ms 떨어진 12표본 평균의 차를 본다. 중력은 이 축에 대한 회전 모멘트를 만들지 않으므로 정상적인 수직 하중 이양과 일부 수평 충격을 구별할 수 있다. 반대로 **기저축을 향하는 힘은 모멘트가 거의 없고 작업대 마찰은 모멘트를 만들 수 있다**. 기존 감지기의 경보를 지우지 않는다.

하중·무게중심 조합 16개의 **무충돌** 동작에서만 한계를 정했다. 100 ms 구간과 양옆 구간의 최대 진폭에 무게중심을 한 그룹씩 뺐을 때 생긴 여유값과 5%를 더했다. 충돌 시간표·실제 외력·미래 샘플은 감지기에 전달하지 않는다. [설계·정상 보정](../results/r21/calibration.json). 이와 달리 표의 ‘집기 구간 힘 예측’은 정상 수평 힘의 **부호 있는 시계열**을 적합한 별도 후보다. 이 후보의 [잡음 시드 결과](../results/r21/pick_noise.json)는 회전 모멘트 방식의 성적으로 세지 않았다.

센서 잡음의 난수 시드만 11·29·41·53으로 바꾼 임시 복사본에서도 같은 모델을 시험했다. 기존 R20은 10 N을 **0/16**, 회전 모멘트 옵션은 **16/16** 구별했다. 네 시드에서 0·8 kg의 집기 직후 지연은 43–47 ms, 놓기 직전은 86–97 ms였다. 이 실험에서는 충격당 상승이 한 번이었고 새 오경보는 없었다. 충격의 방향·시각은 이미 알려진 조건이므로 새로운 작업을 검증한 수치로 세지 않는다. [정상 보정 재현·시드 48회](../results/r21/yaw_noise.json).

## 미사용 조건과 연속 충격

- 검출기를 고정한 뒤 별도 담당자가 정한 12개 초기 약충격에서 R10 / R20 / 집기 힘 예측 / 회전 모멘트는 **8 / 8 / 9 / 10건**을 구별했다. 새 이득은 4.5785 kg의 −X 7.5 N(+46 ms), 6.7513 kg의 −Y 8 N(+37 ms)이다. +X 6 N과 +Y 6.5 N은 여전히 놓쳤다. 힘 없는 짝 실험의 같은 시각에 이미 경보가 울린 경우는 성공이 아니다. 실제 공구 접촉 약 206 N은 보존했다. [계획](../experiments/r21_weak_challenge/plan.json) · [두 비교 실행 198회](../results/r21/weak_challenge.json).
- 힘 없음·첫째만·둘째만·둘 다의 네 실험을 비교했다. 충격 벡터와 시점이 맞고, 각 충격에 새 경보가 정확히 한 번이어야 통과다. 서로 다른 네 조건을 기본 작업대와 물성이 다른 작업대에서 실행했다. 기존 R10/R20은 각 **0/8**, 회전 모멘트 옵션은 **4/8**이었다. +Y 10.5 N과 −Y 11 N의 후속 충격을 양쪽 작업대에서 구별했다. 반면 2.7 kg의 X방향 충격 하나에는 **40 ms와 129 ms**에 두 번 울렸다. [표면별 네 가지 짝 실험](../results/r21/surface_pairs.json).
- 원인은 놓기 시각에 감지 이력이 초기화되어 같은 힘이 남아 있어도 다시 경보를 낼 수 있다는 점이다. 별도 후속 실험에서는 놓는 물체가 가져가는 각운동량만 빼고 나머지 이력을 보존했다. 기존 **4/8 → 8/8**, 미리 정한 새 조건은 **4/6 → 4/6**이었다. 7.13 kg에서 간격 136 ms인 두 힘은 둘 다 넣었을 때 둘째 시작 전에 경보가 가라앉지 않았다. 새 상승이 있어도 독립 경보로 세지 않았다. 이 보정은 기본 파일·ZIP에 넣지 않았다. [기존·새 결과와 판정 근거](../results/r21/release_history.json).
- 서보에서도 비슷한 관측기로 공식 23→24가 가능했지만, 큰 충격이 끝난 뒤 **3.862 s에 새 오경보**가 생겼다. 지지력·마찰로 설명할 수 있는 회전 모멘트를 제외해도 보호 시험 4조건 중 2조건이 실패했다. **서보 후보는 기각했다.** ZIP의 서보 동작은 기존 R10(23/24)으로 돌아간다. [반례](../results/r21/servo_veto.json).

## 전체 385조건을 확인하니 기본 제출로 쓸 수 없는 이유

기존 D4 개발 세트 전체(무충돌 기준 189, 충돌 180, 오프셋 16)를 R10과 회전 모멘트 옵션으로 각각 실행했다. **770회 실행에서 네 가지 실제 회귀**가 남았다.

| 조건 | R10과 달라진 점 |
|---|---|
| 174: 8 kg, 무게중심 Z −2 cm, 충격 없음 | R10은 조용했지만 새 옵션은 1.709 s에 경보를 냈다. |
| 330: 놓기 구간 −X 15 N | R10이 놓친 충격을 찾았으나 한 충격에 두 번(3.879 / 3.946 s) 울렸다. |
| 339 / 349: 놓기 구간 +X 25 / 40 N | 같은 한 충격에 대한 상승이 각각 2→3회, 1→2회로 늘었다. |

전체 기록의 충돌 검출 수는 **111/180 → 136/180**, 기존에 검출했던 충돌의 손실은 없었다. 이 숫자와 보수적 진단을 모두 통과한 부분집합을 구분한다. 이전 진단은 명목 시작 샘플에서 힘이 정확히 0이어야 한다고 가정했고, 벡터 전체의 크기 계산도 원본과 연산 순서가 달랐다. 최초 판정의 104개 실패 행을 숨기지 않았다(102개는 진단 조건 실패, 실제 회귀와 일부 겹침). 별도 실험에서 **180/180** 실제 입력 벡터와 원본의 표본별 힘 크기가 허용오차 없이 일치했다. 처음부터 모든 입력 진단을 통과한 충돌 78조건에서도 **42→58건**이었고, 이 중 330번은 여전히 중복 경보였다. 실제 회귀는 집계 방법을 바꿔서 해결할 수 없다. [판정과 입력 감사](../experiments/r21_full_protection/summary.json) · [기본 파일명 소규모 대조](../results/r21/standalone_screen.json). 이 조건들은 공개 개발 세트이지 새로운 비공개 시험이 아니다.

## 로컬 재현

원본 키트는 배포하지 않는다. 아래 명령은 배포 저장소의 루트에서 실행한다. `KIT`는 제공받은 원본 `icpbl_sim` 디렉터리, `OUT`은 키트와 저장소 **밖**에 이미 있는 출력 디렉터리다. 각 결과 이름은 새 것이어야 한다.

```bash
# 원본 평가기로 검증한 뒤 선택형 토크 ZIP 만들기
python -B tools/r21_torque_package.py --kit "$KIT" --out "$OUT/torque-yaw.zip"
# 사전에 고정한 약충격·연속 충격·이력 보정 비교
python -B tools/r21_replay.py --kit "$KIT" --study weak    --out "$OUT/weak"
python -B tools/r21_replay.py --kit "$KIT" --study surface --out "$OUT/surface"
python -B tools/r21_replay.py --kit "$KIT" --study history --out "$OUT/history"
# 확장 385조건·정확한 입력 재감사; 보호 판정 FAIL이 재현되어야 함
python -B -m tools.r21_d4_check --kit "$KIT" --out "$OUT/d4" --workers 3
# 정상 보정값 재생성 및 잡음 시드만 바꾼 인증 복사본 대조
python -B tools/r21_yaw_checks.py --kit "$KIT" --out "$OUT/noise.json"
```

[ZIP 파일 목록·해시·기본 채택 거부 판정](../results/r21/package.json). ZIP 안의 코드 두 개는 R10에서 가져온 `torque_controller.py`와 한 파일로 조립한 `collision_detector.py`이다. 기본 수업 데모가 필요하면 이 파일을 사용하지 않는다. ZIP을 시험할 때도 **원본에는 덮어쓰지 말고** 별도의 실험 복사본을 쓴다. 공식표와 위 검증은 유한한 CPU 시뮬레이션의 결과다. 미사용 모든 조건, 하드 실시간, 실물 안전을 입증하지 않는다.
