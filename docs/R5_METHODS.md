# R5: 제어기를 바꾸지 않는 정상-only 학습 감지

A는 서보, B는 토크 방식, FA는 오감지다. 최종 채택 여부는
[결과](R5_RESULTS.md)에서 별도로 판정한다. 여기서는 사전 고정한 수식과 검사를 설명한다.

## 입력과 학습 분할

- 입력은 엔코더·차분 속도, 모터 토크·관절 토크 센서, 그립, 공개 reference,
  알려진 질량·COM과 이들로 계산한 R1 관측기 렌치·관절 잔차뿐이다.
- 실제 링크각·토크·외력·접촉력·작업대 힘, 설정 강성·마찰·센서 시드,
  충돌 시각·힘·라벨은 모델의 특징이나 목표에 들어가지 않는다.
  물리 비교 자료는 별도 파일로 저장하고 입력 로더가 거부한다.
- 정상 적합 24조건/방식, 보정 16조건/방식, 감사 16조건/방식을 서로 다른
  질량·COM·시드로 수집했다. 후속 정상 감사도 새 16조건/방식이다.
  모든 모델과 임계는 최초 정상 자료로 고정하며 후속 결과로 재보정하지 않는다.
- 적합은 NumPy ridge, 추론도 고정 NumPy 계산이다. 설치 패키지는 추가하지 않는다.
  [재학습 도구](../tools/r5_normal_learning.py)는 고정한 정상 적합·보정 역할만 읽고
  현재 모델을 덮어쓰지 않는 새 출력 디렉터리를 요구한다.

## 두 계열과 네 설정

| 계열·설정 | 정상 예측·정규화 | 활성 범위 | 사전 지위 |
|---|---|---|---|
| SCALE_PHASE | R1 정상 예측에 위상별 중앙값을 더하고 위상 MAD로 나눔 | R1과 같은 활성 범위 | 진단 대조 |
| SCALE_STATE | 같은 중심 보정에 reference·payload 상태의 log-scale ridge를 사용 | R1과 같은 활성 범위 | A/B 채택 가능 후보 |
| AR20_FULL | 20 ms 전 허용 신호와 과거 10표본 평균을 쓰는 정상 ridge | 시작 60 ms 뒤 | 영구 비채택 진단 대조 |
| AR50_FULL | 위와 같은 구조, 지연만 50 ms | 시작 60 ms 뒤 | 영구 비채택 진단 대조 |

SCALE의 “상태”는 주로 **알려진 reference와 payload 상태**다. 실제 링크 상태나
숨은 강성 값을 뜻하지 않는다. AR만 허용 측정의 과거 문맥을 추가한다.
RFF는 사전 분석의 이득 기준에 못 미쳐 실제 후보에서 제외했다.

## SCALE 수식

시간·질량·COM의 기존 정상 특징을 `φ`, 위상 번호를 `p`라 하자.
위상 경계는 1.32, 1.60, 3.75, 4.00 s다. 정상 적합 자료에서만 구한
중심 `b[p]`를 기존 정상 예측에 더한다.

`e[k] = w_hat_XY[k] - (mu_R1(φ[k]) + b[p[k]])`

SCALE_PHASE는 적합 잔차 norm의 위상 MAD × 1.4826을 쓰고 하한은 0.25 N이다.
SCALE_STATE는 `x = [φ, 위상 one-hot, grip, mass × grip]`의 정상 잔차 log 크기를
ridge 계수로 예측한다. 표준화는 적합 자료만 사용하고 ±8에서 자른다.

`s[k] = clip(exp(a0 + a^T z(x[k])), 0.25, 1000)`, `score[k] = ||e[k]|| / s[k]`

SCALE_STATE의 추가 실수 파라미터는 방식별 263개다. 위상별 중심과 스케일,
표준화 계수는 적합 자료에서만 정하며, 보정 자료로 바꾸지 않는다.
적합에서 활성 표본이 없던 위상은 새 분기를 끈다. 수치 placeholder로 경보를 내지 않는다.

## AR 수식과 인과성

추가 과거 특징은 `w_hat_XY` 2개, 관절 잔차 6개, 엔코더-reference 오차 6개와
지연 시점에서 끝나는 과거 10표본 XY 평균 2개다. 현재·미래 렌치 목표를 입력으로 쓰지 않는다.
예측 후 현재 관측을 60표본 ring buffer에 넣으며 실행마다 초기화한다.
정상 가중치와 위상 MAD는 적합 자료에서만 정한다.

AR은 사전 분석에서 충돌 밖 오감지를 늘렸다. 새 조건에서 진단 이득이 나타나도
채택 대상으로 되살리지 않는다. 이는 LSTM을 재현한 것이 아니다.

## 보정·경보와 기존 검출 보존

점수 EMA의 계수는 0.1이다. 별도 정상 보정 실행마다 활성 4연속 EMA의 최솟값을
구하고 그 최대에 1.05를 곱한 뒤 `1e-12`를 더해 임계를 고정한다.
엄격한 `EMA > threshold` 4연속이면 켜지고, 8표본 연속 이하이면 꺼진다.
비활성에서는 EMA·계수·래치를 즉시 초기화한다.

최종 경보는 `R1 경보 OR 새 분기`다. 부모 감지기는 한 번만 호출한다.
실제 R1 활성 인자는 감지기 소유 정상 모델의 수동 기록 subclass로 받으며
공유 estimator·nominal 객체에 새 값을 저장하거나 추가 동역학 함수를 호출하지 않는다.
반환하는 원래 관절 잔차와 두 제어기는 그대로 둔다.

## 탄성 관절·1 ms·지연에 대한 경계

기존 탄성 관절, 1 ms ZOH, 한 주기 지연 상태를 `z`, 새 감지기 상태를 `xi`라 하자.
키트의 제어 입력은 `xi`나 경보를 참조하지 않으므로 결합 국소 Jacobian은
`[[J_R1, 0], [B, J_monitor]]` 형태다. 기존 플랜트·제어 블록은 바뀌지 않는다.
고정 활성 구간의 EMA pole은 0.9이고 AR 과거창은 유한 shift 기억이다.

그러나 gate·clip·래치는 비매끄럽고 R1 자체의 국소 실패점도 남아 있다.
이 설명은 로봇 전체의 전역 안정성 증명이 아니다. 실제 fresh full-loop에서
물리 8배열의 비트 일치와 온라인/오프라인 경보 일치를 확인한다.
키트의 이상적 1 ms 적분도 실제 PC의 hard real-time 보장은 아니다.

## 평가 순서와 자료의 독립성

정상 감사 → 실제 동등성 → validation → 재설계 결정 → development → D4·섭동 →
동결 → 새 holdout 한 번 → 원본 평가기 회귀 한 번 순서다.
모두 동결 전에 탈락하면 마지막 두 실행은 생략한다.

사전 구현 검사에서 예약 holdout 377650의 실제 조건이 최소 12회 생성된 절차 위반이 있었다.
물리 실행·성능 평가·학습·후보 선정에는 쓰지 않고 해당 설계와 센서 예약을 폐기했다.
폐기 질량 네 개를 제외하는 용도로만 추가 복원했으며, 같은 관문 아래 새 377850을
[별도 재봉인](../results/v2_protocol/PROTOCOL_R5_HOLDOUT_RESEAL.json)했다.
새 조건은 동결·Git 검증과 개봉 표식 뒤에만 생성한다. 검사는 실제 protocol이 아닌
합성 protocol·시드만 사용한다. 이 이탈을 “처음부터 미개봉”으로 보고하지 않는다.

validation은 네 설정 전부의 실제 full-loop·직렬 시간을 재며,
development는 동등성 증명 뒤 새 R1 stream에 감지기만 재생한다.
D4 385조건/방식은 이미 노출된 고정 캐시이지 독립 효능이 아니다.
원자료 SHA·출처·조건을 고정했지만 D4의 일부 시드·섭동 값은 원기록에 없어
미상으로 유지한다. 정확한 fresh 재생성은 주장하지 않는다.
섭동 34조건은 기존 25조건(기존 잡음 9조건 포함)과 새 잡음 9조건이다.

추가 검출 최소는 validation 2, development 2, D4 6, holdout 2다.
기존 검출·툴 접촉 손실 0, 조건별 FA 비증가, 정상 감사 새 경보 표본 0,
제어 물리 배열 비트 일치, 합산 p99 ≤ 800 µs를 모두 요구한다.
최대 1 ms는 별도 목표이며 모든 초과값을 보존한다. 전역 GC는 바꾸지 않는다.
문헌의 교환가능성·coverage나 강체 관측기 안정성 정리를 이 플랜트에 옮기지 않는다.
