# R6 방법 — 조립 결함 한 줄 수정과 재검증

## 범위

R6은 R5에서 학습한 A 서보 SCALE_STATE 감지기의 조립 결함만 고친다. 모델 263개 파라미터, 정상 데이터로 정한 임계값, R1 제어기, 평가 관문은 바꾸지 않는다. B 토크는 R1을 유지한다. 재설계는 0회다.

## 결함과 수정

R5 조립기는 서보 하나만 켤 때 모드 집합을 문자열로 만들었다. 정상 공식 평가처럼 제어기 모드가 있으면 우연히 같은 분기 결과가 나오지만, 제어기나 `MODE`가 없는 제출 호환성 호출에서는 membership 검사가 예외를 냈다. R6은 이 값을 한 원소 튜플 `('servo',)`로 만든다.

회귀 검사는 모드가 하나와 둘인 경우, `MODE=None`, 모르는 문자열, `MODE` 속성이 없는 제어기, 제어기가 없는 경우를 포함한다. 수정 전 알려진 예외를 재현하고 수정 후 모두 안전하게 R1 분기로 꺼지는지 확인한다.

## 동결 전 검증

최종 조립 파일을 `my_detector.py`와 `collision_detector.py`라는 기본 제출 이름으로 놓은 격리 사본에서 전체 단위 검사와 제출 인터페이스 검사를 실행한다. 제어기 기본 이름도 R1과 바이트가 같아야 한다.

저장 validation·development·D4·섭동 자료는 집계값만 비교하지 않는다. 각 6초 스트림에서 허용된 13개 런타임 신호로 실제 감지기와 제어기를 원래 호출 순서대로 실행한다. A 서보는 동결 R5 A_STATE, B 토크는 R1과 반환 residual, 경보, 내부 packet, 점수와 EMA를 dtype·shape·바이트 단위로 비교한다.

별도의 새 시드 조건에서는 실제 full-loop를 짝지어 실행하고 `q`, `q_d`, `tau`, `e_mm`, `f_table`, `f_tool`, `qpos`, `r`의 8개 물리 배열을 같은 방식으로 비교한다. 허용오차는 쓰지 않는다.

## 봉인 순서

아래는 S1 통과 시 예정한 절차다. 실제 R6은 S1 결과 기록 실패로 멈춰 정식 protocol·동결·holdout·공식을 실행하지 않았다.

1. 저장 자료 및 새 full-loop 비트 동등성을 확인한다.
2. 새 holdout 시드와 실패 규칙을 담은 `PROTOCOL_R6.json`을 커밋한다.
3. 후보와 R1 fallback, 실행 도구와 입력 SHA를 동결하고 커밋한다.
4. marker를 fsync한 뒤 실제 holdout 난수 생성기를 한 번만 연다.
5. 38조건을 방식별 R6 파일과 R1로 짝지어 한 batch 실행한다.
6. holdout이 통과하면 후보를, 실패하면 즉시 선택한 R1 fallback을 기본 제출 이름으로 놓고 원본 공식 평가를 한 batch 실행한다.
7. 최종 조립 파일로 전체 검사와 제출 인터페이스 검사를 다시 실행한다.

어느 단계든 실패하면 후보를 고치거나 관문을 완화하지 않고 미리 동결한 R1을 고른다. holdout이나 공식 결과를 본 뒤 재실행하지 않는다.

## 관문

서보 후보 holdout은 추가 검출 2 이상, R1 검출 손실 0, 도구 접촉 손실 0, 조건별 FA 비증가, 정상 reference FA 0, 물리 8배열 비트 일치, 합산 p99 800 µs 이하를 요구한다. 토크는 추가 검출 목표 대신 R1 경보·물리값 동일성을 확인한다. 최대 1 ms는 목표이며 관문이 아니다. 초과 주기와 최대값을 모두 남긴다.

공식 회귀는 0/4/8 kg 무충돌 FA 0/0/0, 포화 0 %, 비발산, 기존 R1 검출 보존, 운반 지연 +5 ms 이내를 요구한다. B 토크는 R1과 같은 결과여야 한다.

## 공식 결과 필드

과거 R5 공식 JSON에는 R5 후보 값을 `R3_delay_ms`와 `R3_false_alarms`로 부른 호환 필드가 있다. 원자료는 보존한다. R6은 시험 대상 값을 `tested_delay_ms`와 `tested_false_alarms`로 기록해 의미를 명확히 한다.

## 재현 한계

S1 사전 소스 잠금·중단 기록의 작업 커밋 해시는 비공개 연구 작업 이력이다. 공개 저장소 이력에서는 해당 작업 해시를 찾을 수 없으며, 공개 파일의 바이트는 배포 SHA256 목록으로 확인한다. 정식 R6 protocol·동결 기록은 만들지 않았다.

공개 결과에는 조립기, 모델, S1 사전 소스 잠금·중단 스냅샷·실패·사후 배열 검토·R1 판정 JSON, 저장 자료 검증 집계와 문서 도구를 제공한다. 정식 R6 protocol·동결·holdout·공식 결과는 없다. 원시 시계열과 취득 드라이버는 공개하지 않는다. 저장 자료 동등성은 결과 승계 근거이지 새 효능 시험이 아니다. 유한 시뮬레이션은 하드웨어 안전 보장이나 충돌 정지 인증이 아니다.

## 실제 R6 조기 종료

S1 새 full-loop 8회는 완료됐지만 결과를 모으는 마지막 JSON 직렬화에서 토크 monitor 비교 flag가 `numpy.bool_`로 남아 표준 encoder가 거부했다. 동결 전 전체 검사와 기본 제출 계약은 통과했지만 이 토크 비교 직렬화 경로를 실행하지 못한 검사 공백이 있었다. 규칙에 따라 driver·sealed 도구·후보·모델을 고치거나 수집을 다시 실행하지 않고 R1 fallback을 선택했다.

사후 read-only raw 검토에서는 8회의 물리 배열, packet, 최종 결정과 해당 monitor 비교가 모두 비트 일치함을 확인했다. 이 검토는 실패한 transaction을 수리하거나 S1 통과로 바꾸지 않는다. 따라서 protocol·holdout 조건·공식 결과 JSON은 만들지 않았고 holdout과 공식 실행은 각각 0회다.
