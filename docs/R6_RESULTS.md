# R6 결과

## 판정

S1 결과 직렬화 실패로 R6 후보를 채택하지 않고 A 서보와 B 토크 모두 R1을 유지했다. holdout과 공식 평가는 열지 않았다. 결함 수정 외 재설계는 0회다. 실제 S1 실패 뒤 검증 드라이버·후보·모델·임계값·관문을 고치거나 실험을 재실행하지 않았다.

## 결함과 검사

- 원인: 한 원소 모드 집합이 문자열로 생성돼 제어기 모드가 없는 `reset()`에서 예외가 발생했다.
- 수정: 문자열 한 줄을 한 원소 튜플로 바꿨다. 모델, 임계값, 제어기에는 차이가 없다.
- 알려진 결함 재현 검사는 수정 전 실패했고 수정 후 통과했다.
- 초기 전체 534개와 최종 동결 전 전체 592개, 기본 이름 8개 검사가 통과했다.
- 첫 전체 검사 1회는 검증 사본의 저장소 메타데이터가 없어 환경 무효로 분류했다. 533개는 통과했고, 감지기 행동을 보지 못한 저장소 조회 검사 1개만 오류였다. 소스 바이트를 그대로 둔 유효 환경에서 같은 534개를 통과했다.

## 동등성

새 full-loop 8회는 모두 완료됐고 사후 raw 검토에서 물리·packet·결정 비트가 같았다. 그러나 결과 직렬화가 실패했으므로 이 사후 검토는 실패한 S1 transaction을 수리하거나 통과로 바꾸지 않는다.

- 저장·S1 상태: S1 transaction 실패·사후 raw 8회 비트 검토만 통과
- 새 full-loop 결과 transaction: 직렬화 실패
- 비교 배열: `q`, `q_d`, `tau`, `e_mm`, `f_table`, `f_tool`, `qpos`, `r`
- 허용오차를 쓰지 않았으며 dtype·shape·C-order 바이트를 모두 비교했다.

실패 원인은 토크 monitor 비교 flag가 `numpy.bool_`인 상태에서 표준 JSON encoder로 직렬화된 것이다. 이 알려진 도구 결함은 후보·driver·sealed 도구를 고치지 않고 그대로 실패로 처리했다. 사후 raw 검토는 원시 8회가 완료됐다는 사실만 확인하며 실패 transaction을 복구하지 않는다.

## 미달

- 새 holdout 계산 시간은 미실행이다. 최대 1 ms를 보장으로 주장하지 않는다.
- 무충돌 섭동 28 reference FA는 A 6→6, B 9→9다.
- 전체 34조건 FA는 A 6→6, B 10→10다. 28 reference 범위와 섞지 않는다.
- 탈락한 B STATE 진단값은 D4 추가 +5로 기준 6에 못 미쳤고, 28 reference FA가 9→10로 늘었다. R6 B에는 승계하지 않았다.
- 놓기 전 평균 지지율은 R1에서 A 0.2098; B 11.1507로 50 %mg 기준에 못 미친다.
- D4 R1 포화/놓기 peak는 A sat 2/189, peak 1.6098 mg; B sat 0/189, peak 1.0358 mg로 A 포화 0회와 peak 1.1 mg 기준을 만족하지 못한다.
- 유한 시뮬레이션 결과이며 하드웨어 안전 보장이나 충돌 정지 인증이 아니다.

## 공개 재현 범위

공개 파일에는 조립기, 모델, 검증 집계, 문서 생성기와 검사 도구가 들어간다. 비공개 원시 시계열과 취득 드라이버는 포함하지 않는다. 정식 protocol·동결·holdout·공식 결과는 만들지 않았다. 실제 기록은 [실패](../results/v2_protocol/R6_S1_FAILURE.json), [사후 배열 검토](../results/v2_protocol/R6_PARITY_RAW_REVIEW.json), [중단 시 소스 잠금](../results/v2_protocol/R6_STOP_SNAPSHOT.json), [저장 동등성](../results/v2_protocol/R6_SAVED_EQUIVALENCE.json), [판정](../results/v2_protocol/R6_ADOPTION.json)이다.
