# Week09 최종 제출본 — R1 제어 + 모드별 충돌 감지기

[README로 돌아가기](../README.md) · [문서 색인](INDEX.md)

**과제 제출 파일은 [`submission/`](../submission/README.md)의 세 파일이다.** 수업 원본 평가기로 수평 충돌 24건을 시험한 결과 **서보 24/24, 토크 24/24**를 검출했다(이전 제출 R10은 23/24, 18/24). 충돌이 없는 동작의 오경보는 두 방식 모두 0회다. 제어기 두 파일은 R1 그대로이고, 바뀐 파일은 충돌 감지기 `my_detector.py` 하나다.

## 무엇을 조합했나

| 파일 | 내용 | SHA-256 |
|---|---|---|
| `my_servo.py` | R1 서보 제어기, 변경 없음 | `40706968…` |
| `my_torque.py` | R1 토크 제어기, 변경 없음 | `8f66f8f0…` |
| `my_detector.py` | 감지기 하나에 세 방식을 담았다. 제공 토크 제어기와 함께면 **R31**(토크 연구 감지기), 제공 서보 제어기와 함께면 **R32**(서보 연구 감지기), 그 밖의 제어기와 함께면 **R10**을 쓴다. | `010f8a1c…` |

- 방식은 `reset()`에서 한 번 고른다. 1 ms 루프에서는 고른 방식의 `update`만 호출하므로 분기 비용이 없다.
- R31과 R32의 연구 코드와 정상 모델 수치는 그대로 한 파일에 연결했다. 새 검출 규칙, 문턱값 조정, 모델 재학습은 없다.
- 토크 부분은 이전에 검증한 R10 서보 + R31 토크 결합본(`f1c8c3be…`)과 바이트 단위로 같다.
- 저장소 루트의 `my_detector.py`는 연구 후보들이 상속하는 R10 기준 감지기라서 그대로 두었다.

## 후보를 고른 근거

모든 후보를 수업 원본 평가기로 각각 29회 실행했다. 원자료는 [`results/final/official/`](../results/final/official/servo_r32.txt)에 있다.

**서보:** R32가 R10이 놓치던 **0 kg·3.86 s·10 N** 충돌을 131 ms에 검출해 23/24에서 24/24가 됐다. 나머지 23칸, 무충돌 제어표, 오경보 0회는 R10과 같다.

**토크:** R31, R33, R34는 공식 평가의 비시간 셀이 모두 같았다(24/24). 그래서 공개 385조건 시험에서 오경보 9회·중복 2회로 가장 적은 R31을 골랐다. R34는 같은 시험에서 180/180을 검출했지만 오경보 15회·중복 4회였다.

토크 충돌 감지 지연(ms; 10/15/40/100 N 순)은 모든 칸에서 이전 R10과 같거나 짧다.

| 박스·충돌 시각 | 이전 R10 | 최종 (R31) |
|---|---|---|
| 0 kg·1.42 s | 놓침 / 놓침 / 37 / 22 | 38 / 34 / 26 / 19 |
| 0 kg·3.00 s | 57 / 42 / 27 / 19 | 57 / 38 / 25 / 19 |
| 0 kg·3.86 s | 놓침 / 78 / 30 / 19 | 49 / 42 / 30 / 19 |
| 8 kg·1.42 s | 놓침 / 놓침 / 36 / 24 | 43 / 37 / 27 / 22 |
| 8 kg·3.00 s | 56 / 43 / 26 / 18 (오감지 1회) | 56 / 41 / 25 / 18 (오감지 1회) |
| 8 kg·3.86 s | 놓침 / 91 / 42 / 22 | 86 / 86 / 38 / 22 |

8 kg·3.00 s 충돌 실행의 오감지 1회는 R10에도 있던 값이다. 무충돌 추종 성능은 이전과 같다. 8 kg 기준 RMS는 서보 1.17 mm, 토크 3.23 mm다.

## 검증

- **공식 평가:** 정품 키트 복사본에 ZIP을 풀고 학생 파일명(`my_*`)과 수업 기본 파일명 두 방식으로 서보·토크를 실행했다(총 116회). 비시간 셀이 기대값과 모두 일치했고 키트는 바뀌지 않았다. [verification.json](../results/final/verification.json)
- **단계별 일치:** 대표 16조건(서보 6·토크 10)에서 물리 궤적, 잔차, 경보, 가한 외력 배열이 R32·R31 연구 모듈 실행과 비트 단위로 같았다. [parity.json](../results/final/parity.json)
- **대체 경로:** 수업 기본 제어기와 함께 쓰면 R10과 비시간 셀이 같다. [서보](../results/final/official/fallback_stock_servo_final.txt) · [토크](../results/final/official/fallback_stock_torque_final.txt)
- **재현 가능한 빌드:** 아래 빌더를 다시 실행하면 같은 바이트의 ZIP이 나온다(SHA-256 `2a3850363e1a6eee6fffb15e1210bbf7b2607f71d4179f76d2d2799b2b713ab5`). [build.json](../results/final/build.json)

## 재현

원본 키트와 출력 경로는 저장소 밖의 새 경로를 쓴다.

```bash
python -B tools/build_final_submission.py --out /path/to/new-build
python -B tools/verify_final_submission.py \
  --zip /path/to/new-build/week09-final-r32-servo-r31-torque.zip \
  --kit /path/to/icpbl_sim --out /path/to/new-result
python -B -m unittest tools.test_build_final_submission
```

단계별 일치 검사(`tools/parity_final_submission.py`)는 다른 연구 재현 도구와 마찬가지로 키트 오버레이에서 실행한다. 키트 오버레이는 이 저장소 복사본에 원본 키트의 `sim/`, `model/`, `evaluate.py`를 더한 것이다.

## 한계

- **R32 서보:** 별도 64회 검증에서는 R10과 결과가 같았다(손실 0, 추가 검출 0). 연구 단계의 사전 기준은 추가 검출을 요구했기 때문에 미채택이었다. 최종 제출에서는 공식 평가에서 손실 없이 1건을 더 잡은 점을 근거로 채택했다.
- **R31 토크:** 새 단일 충격 12건을 모두 검출했고 오경보는 0회였다. 다만 5건은 첫 경보가 4 ms로 짧아 연구 단계의 최소 유지 시간 기준을 넘지 못했다. [R31 문서](R31_COLLISION_IDENTITY.md)
- **공식 평가 조건:** 공식 24건은 개발 중 공개된 조건이다. 다방향·연속 충격과 독립 시험 결과는 각 라운드 문서에 있다. 실기와 1 ms 하드 실시간은 검증하지 않았다.
- **수업 원본 시연:** 원본 시연은 제공 예제 그대로다([DEMO_SOURCES.md](DEMO_SOURCES.md)). 연구 최고 기록은 [FINAL_WEEK09.md](FINAL_WEEK09.md)에 정리했다.
