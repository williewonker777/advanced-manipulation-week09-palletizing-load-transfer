# R10 제출 — 감지기를 더 빨리 준비하되 같은 충격에 같은 경보를 낸다

실제 변경 파일은 [`my_detector.py`](../my_detector.py)다. R1 서보·토크 제어기와 토크 감지 계산은 바꾸지 않았다. 최대 힘을 낮추거나 경보를 무음 처리하지 않았으며, 사전에 정의되지 않은 충돌을 더 잘 검출한다고 주장하지 않는다.

## 무엇을 줄였나

이전 [FAST2](../experiments/r9_final/FAST2.py)는 양의 페이로드에서 동역학 모델 7개를 따로 준비했다. R10은 공칭 빈 모델·하중 모델·차분 전용 모델 **3개**를 사용한다. 기하 계산은 빈 모델의 읽기 전용 구조만 공유하고 계산 상태는 별도다. COM의 네 변위값을 초기화 때 저장해 두었다가, 구속 또는 비수직축 때문에 해석식 대신 차분이 필요할 때만 전용 모델의 하중을 바꾸어 차례대로 계산한다. 루프 중에는 모델을 조립하지 않는다. 서보 기준궤적 표도 행별 축약 순서를 유지한 채 입력 특성을 묶어 준비한다.

## 첫 실행 — 실제 제출 파일과 보관 버전을 교대로 비교

각 행은 서로 다른 새 Python 프로세스 여덟 번(4쌍)이다. 표의 시간은 **감지기 모듈 import + 최초 detector.reset()**이다. Python을 띄우거나 시뮬레이터와 제어기를 준비하는 전체 시간이 아니다. 배수는 가장 빠른 FAST2를 가장 느린 R10으로 나눈 값이다. 같은 컴퓨터에서도 부하·스케줄링에 따라 변한다.

| 측정 | FAST2 (ms) | R10 (ms) | 보수적 배수 |
|---|---:|---:|---:|
| [동결 설계 첫 실행](../results/r10/startup_initial.json) | 259.04–271.58 | 112.11–115.03 | 2.252× |
| [같은 설계를 별도 실행](../results/r10/startup_repeat.json) | 261.64–270.54 | 113.65–117.58 | 2.225× |
| [배포 CLI·다른 CPU 코어](../results/r10/public_startup.json) | 272.34–276.09 | 111.02–115.09 | 2.366× |

[사전 고정 기준](../experiments/r10_scratch/PREREGISTERED_PLAN.json)은 2배 이상, 토크 초기화 및 import 부담 증가 각각 10 ms 미만, 실제 루프 최악 p99 800 µs 이하, 서보 최악 p99 증가 5% 이하다. 첫 두 측정이 모두 통과했다. 측정 장치의 첫 시도는 결과 직렬화 전 계획 키 이름을 잘못 읽어 실패했다. 장치의 키 이름만 고친 뒤 같은 설계 전부를 실행했다. 후보·조건·관문은 바꾸지 않았다.

## 감지가 그대로인지 따로 검사했다

- 세 하중의 기준표 6,000행과 두 grip 상태, 임의 자세·속도·가속도 128개를 반복·역순으로 비교했다. 실제 관절 구속 32개, 비수직축 차분 32개의 결과도 이전 독립 모델들의 결과와 수치적으로 같았다.
- 4개 서보와 2개 토크 물리 조건에서 두 제출 조합의 제어 출력·물리량·잔차·경보·분기 해시가 같았다. 같은 설계를 별도로 다시 실행해 확인했다. 과거 R8 [서보 114개](../results/r10/servo_r8_replay.json)와 [토크 114개](../results/r10/torque_r8_replay.json)에서도 방식당 684,000주기의 잔차·기본 경보·최종 경보 바이트를 대조했다. 보관 신호 재생이지 새로운 검출 성과는 아니다.
- 배포 트리에 허가된 키트를 임시 조립하고 실제 기본 이름으로 원본 평가기를 돌렸다. 두 방식 29회씩 총 **58회, 비시간 132개 셀**이 이전과 같았다. 수평 충돌은 서보 **23/24**, 토크 **18/24**였다. [R10 공식 결과](../results/r10/official_regression.json) · [보관 R9 결과](../results/r9/official_regression.json).
- 별도 고정 크기 계측으로 같은 정상 조건 12회를 방식별로 반복했다. **72,000주기씩**에서 제어+감지의 최대 wall은 [서보 565.16 µs](../results/r10/servo_deadline.json), [토크 583.72 µs](../results/r10/torque_deadline.json)였다. 이 측정과 두 개발 실행에서 후보의 1 ms 초과를 관찰하지 않았어도, 전체 시뮬레이터·OS·실기에 대한 하드 실시간 보장은 아니다.

## 재현

원본 키트에 쓰지 않는다. 저장소 루트에서 키트 의존성이 설치된 Python을 사용한다. JSON 출력은 새 파일, 공식 평가 출력은 새 디렉터리를 지정한다.

```bash
KIT=/path/to/icpbl_sim
python tools/r10_startup.py --kit "$KIT" --out /path/to/new-startup.json --pairs 4
python tools/validate_submission.py --kit "$KIT" --out /path/to/new-r10 --check-release
python tools/validate_submission.py --kit "$KIT" --out /path/to/new-r9 --archived-r9 --check-release
```

시작 시간 도구의 `--cpu N`은 현재 프로세스에 허용된 CPU 중 하나에만 고정하는 선택값이다. 모든 개별 시간, 버전, 출처 해시와 산식을 기록한다. 실행 환경이 다른 경우 시간 수치까지 같을 필요는 없다.

**남은 문제:** [놓기 직전 하중 지지(G4), J2 포화와 토크 약충돌](R10_COMPARISONS.md), [충격 뒤 토크 모드 위치 복귀](R10_RINGDOWN.md)는 초기화 변경으로 해결되지 않는다. 이들에 대한 후보는 별도 비용이나 감지 기준을 넘어서서 제출하지 않았다. 실기와 비공개 조건은 평가하지 않았다.
