# R4: 고정 정상 보정과 순차 충돌 감지

A는 서보, B는 토크, FA는 오감지다. 제어기는 두 방식 모두 R1을 그대로 쓴다.
이 문서는 [사전 계획](../results/v2_protocol/PROTOCOL_R4.json)의 구현 설명이며,
채택 여부와 실제 수치는 [결과](R4_RESULTS.md)에 둔다.

## 구현 용어를 읽는 법

결과와 발표에는 쉬운 표현을 쓰고, 코드와 대조할 때 필요한 용어만 여기에 둔다.
추가 감지 계산을 감싸는 코드가 wrapper, 먼저 실행되는 기존 R1 감지기가 parent,
높이 판정을 계산하는 작은 함수가 helper다. nominal은 공개 파라미터로 만든 명목 모델,
scratch는 그 계산에 쓰는 임시 저장 공간이다. literal no-store는 최종 값이 같더라도
공유 공간에 다시 쓰는 행위 자체를 금지한다는 뜻이다. certificate는 새 실행과 재사용 행을
구분한 동일성 검사 기록, marker는 중복 실행을 막기 위해 한 번만 만드는 시작 기록,
family는 같은 원리의 후보 계열을 뜻한다. 이 용어들은 새 성능 보장이나 채택 근거가 아니다.

## 원인에서 후보로

[구현 전 분석](R4_CAUSE_ANALYSIS.md)은 R1 D4 개발 캐시의 놓침 69개씩을 전부
보존했다. 높이 gate 때문에 learned 분기가 물리 펄스 전체에서 꺼진 놓침은 A 43개,
B 46개였다. 이는 그 분기의 배제 원인이지 전체 OR 감지기의 단독 실패 원인은 아니다.
같은 정상 자료의 최대 경계에서 후행 40 ms 평균은 추가 17/15개를 분리했다.
4표본 연속 조건에서는 13/14개다. 이 비독립 진단 경계를 운용 임계값으로 쓰지 않는다.

일곱 점수 중 어느 것도 정상 전역 최대 경계를 넘지 못한 놓침은 A 52/B 53건이다.
구현은 정상 최대값의 바로 다음 부동소수 값(`nextafter`)을 경계로 만들고 엄격한 초과를
검사한다. 추가 원자료 대조에서도 이 52/53건의 평가창 최댓값은 원래 정상 최대값을
넘지 않았다. 정상 189조건과 놓침 평가에 같은 개발 자료를 쓴 진단이지,
새 자료의 성능 상한이나 모든 허용 신호의 구분 불가능성에 대한 증명은 아니다.

## 직접 쓴 식과 1 ms 구현

허용된 추정 wrench의 수평 성분을 \(\hat f_{xy,k}\), 고정 R1 정상 예측기를
\(\mu(t_k,m,c)\)라 두면 점수는

\[
v_k=\|\hat f_{xy,k}-\mu(t_k,m,c)\|_2
\]

다. 부호·축별 충돌 임계값을 따로 선정하지 않는다. 예측기의 기존 질량·COM 연속
특성은 보존하며, 새 보정은 질량·COM·방향별 lookup을 만들지 않는다. CUSUM은

\[
S_k=\max\{0,S_{k-1}+(v_k-a_j)/b_j-\kappa\}
\]

로 구현했다. \(a_j\)는 새 정상 fit의 중앙값, \(b_j\)는
\(\max(1.4826\operatorname{MAD},0.25\,\mathrm N)\)다. 전역 보정은 한 쌍,
구간 보정은 공개 궤적의 경계 0, 1.4, 1.7, 3.6, 3.9, 6.0 s로 나눈 다섯 쌍을 쓴다.
통계량은 1 ms 표본 단위로 누적한다. 각 보정 정상 episode의 최대 통계량을 구하고
\(h_j=1.05\max S+10^{-9}\)로 정한다. 초과는 엄격한 `>`이며 4연속 표본에 켜고
8연속 비초과에 끈다. 시작 시 짧은 창을 쓰고 비활성 시 누적을 비운다.

fit 24개, 경계 보정 24개, 정상 audit 16개를 방식마다 새로 실행한다. 이 정상 자료에
공식 0/4/8 kg 조건이나 충돌 label은 없다. audit은 총 R1 경보를 0으로 요구하는 것이
아니라 **새 추가 분기의 경보 표본이 0인지** 확인한다. 보정·정확한 생성 소스·검사
결과는 첫 충돌 전에 커밋한다. 충돌 결과로 임계값을 다시 맞추지 않는다.

R1은 gate 비활성 동안 `last_error`를 갱신하지 않는다. 따라서 gate를 제거한 구간
후보만 현재 허용 wrench와 공개 reference 특성으로 오차를 다시 계산한다. 비활성
시점에 오래된 오차를 사용하는 잘못된 구현과 구분한다.

## 비간섭과 안정성의 범위

새 wrapper는 기존 감지기 `update`를 한 번만 부르고 반환 residual을 바꾸지 않는다.
다만 최초 네 설정은 높이 helper를 다시 불러 공유 명목 모델의 qpos·기구학 scratch를
같은 값으로 다시 썼다. 기존 parent가 바로 앞에서 같은 `q_prev`로 계산했고 그 사이
정상 모델은 공개 reference/NumPy만 사용하므로 최종 상태와 물리 비트는 같았지만,
**쓰기 자체 금지에는 미달**이다. 이 동작을 단순 읽기 전용으로 부르지 않는다.

사전 허용된 재설계 1회는 W40에만 사용한다. parent가 이미 계산한 명목 모델의
현재 위치·회전 workspace를 읽어 같은 높이 판정을 만들고 중복 scratch 쓰기만
제거한다. 통계량·가중치·임계값은 바꾸지 않는다. 원래 네 생성 소스와 결과를 보존하고
새 38조건/방식에서 다시 실제 검증한다. CUSUM 세 설정은 원래 구현의 문자적 쓰기
금지 위반으로 영구 비채택이며 이후 측정은 진단이다.
[재설계 사전 추가 계획](../results/v2_protocol/PROTOCOL_R4_REDESIGN_W40.json)과
[당시 정정 결정](../results/v2_protocol/R4_REDESIGN_DECISION_V2.json)에 근거를 둔다.
자동 생성된 초기 미사용 결정은 이 구현 문제를 누락한 불완전한 기록이므로 덮어쓰지
않고 별도 정정으로 남겼다. W40은 원래 validation에서 추가 4/3건과 FA 보존을 보여
이 인과적 수정 대상으로 정했다. 충돌 결과를 이용한 임계값 재선정은 아니다.

수정 W40의 추가 통계량·카운터는 감지기 소유 필드에만 저장한다. 기존 controller의
출력·하중 추정·gain에는 쓰지 않는다. 원래 runner는 검출 bool을 기록만 하고
제어 feedback으로 사용하지 않는다. 따라서 이 조건 아래 폐루프의 탄성 관절,
1 ms ZOH, 1주기 지연은 바뀌지 않는다. 새 제어 후보가 아니므로 새 pole 개선을
주장하지 않으며, 이전 유한 국소 분석을 전역 안정성이나 실기 안전 보장으로 옮기지 않는다.

모든 설정·방식의 새 validation 38개를 직렬 full-loop로 실행해 R1 대비 q, q_d,
tau, TCP 오차, 작업대·툴 힘, qpos, residual 비트를 대조하고 온라인/오프라인 검출도
일치하는지 검사한다. 계산 p99 관문은 800 µs, 최대 목표는 1,000 µs이며 모든
초과 표본을 남긴다. 프로세스 전역 GC 설정은 바꾸지 않는다.

최초 304행 기록을 보존했고, 수정 W40은 새 76행을 실제 full-loop로 검사했다.
최종 16행 certificate는 **새 W40 대표 4행과 소스가 바이트 그대로인 CUSUM의 기존
12행 재사용**으로 구성된다. 16행 전부를 새로 실행한 것으로 쓰지 않는다. CUSUM 세
설정은 문자적 저장 금지 실패로 계속 비채택이며, 수정 W40의 새 비간섭 근거는 전체 76행이다.

OR로 R1 경보 표본을 포함해도 선행 경보가 evaluator의 새 상승 edge를 가릴 수 있다.
따라서 표본 포함성만으로 기존 검출 보존을 선언하지 않고, 같은 조건에서 구분 불가·
masked로 바뀐 경우도 손실로 판정한다. 무충돌 및 충돌 외 구간 FA는 조건별로 늘 수 없다.

## 평가와 사전 고정 판정

새 validation/development는 각각 방식당 정상 4개·충돌 30개·위치 오류 4개다.
충돌은 집기/운반/놓기 × 10개 부호 대칭 방향이며 부호 쌍은 질량·COM·시각·크기가 같다.
추가 검출 관문은 validation 2개, development 2개, D4 6개, 새 holdout 2개다.
모든 이전 관문을 통과해야 하며, 앞서 탈락한 설정은 뒤의 진단 결과로 되살리지 않는다.

D4 385개와 분석 섭동의 물리 행 25개는 hash가 일치하는 기존 R1 관측을 재생한다.
이는 노출된 유한 benchmark이며 새 독립 시뮬레이션으로 부르지 않는다. 섭동 잡음
9개는 새 시드로 실행하며 정상 28개와 외력 6개를 구분한다. holdout은 소스·보정·
선택·평가 도구 동결 후 한 번만 생성한다. 이미 R1으로 탈락한 방식은 새 후보의
holdout 효능을 주장하지 않고 R1 보존 확인만 한다. 공식 평가는 마지막 한 batch의
회귀 확인일 뿐 독립 효능·학습·임계값 선정 자료가 아니다.

재생 행에 남아 있는 `timing`은 원래 물리 스트림의 측정이다. 새 감지기의 계산 비용으로
바꾸어 부르지 않는다. 후보의 채택 p99·최대 비교는 각 설정의 실제 full-loop validation
38행에서만 가져오며, 수정 W40은 새 revalidation 38행을 사용한다.

### 봉인 과정에서 발견한 검사 사고

동결 전 unit 검사 하나가 원래 예정 시드의 실제 설계를 메모리에서 두 번 생성했다.
조건을 출력·저장하거나 해당 holdout episode를 실행하지는 않았지만 사전 생성 금지
위반으로 처리했다. 첫 후보 충돌 결과를 보기 전에
[재봉인 추가 계획](../results/v2_protocol/PROTOCOL_R4_HOLDOUT_RESEAL.json)을 커밋해
그 시드를 폐기하고 새로운 미사용 시드를 봉인했다. 원래 관문·조건 범위는 바꾸지
않았다. 검사에는 완전히 가짜 계획·시드만 사용하도록 고쳤다. 실제 새 holdout은
추가 계획까지 동결한 뒤 배타적 marker 후에 한 번만 생성한다. 이 사고를 숨기거나
원래 시드의 사전 생성이 0이었다고 주장하지 않는다.

W40 재설계의 새 validation 질량 1.5173, 3.8051, 6.0473, 7.2303 kg은 동결 전에
holdout 배제 집합에 추가했다. 수치 관문과 생성 범위는 같지만, 이 네 질량을 다시
시험하지 않도록 배제 집합은 넓어졌다. 전체 설계가 바뀌지 않았다고 표현하지 않는다.

사전 계획·보정·정정에 적힌 커밋 해시는 연구 작업 이력이다. 공개 이력과 구분하며,
공개 파일의 바이트는 체크섬 목록과 보고서 입력 manifest로 대조한다.

## R1도 실패한 관문의 사전 해석

R3의 일부 국소점과 D4 포화 상한은 R1도 실패했다. 원래 radius, 포화 2회/0.15%,
비용 1.05배 숫자는 바꾸지 않는다. R1 통과점에서는 후보도 통과해야 하고 R1 실패점은
R1보다 나빠지면 안 된다. 허용 수치 오차는 사전에 **0**으로 고정했다. 감지기만
바꾸는 이번 후보는 물리 비트가 같아야 하므로 이 해석을 제어 개선으로 쓰지 않는다.
G4 지속 지지 기준도 완화하지 않았고, 달성하지 못한 경우는 계속 미달로 남긴다.
