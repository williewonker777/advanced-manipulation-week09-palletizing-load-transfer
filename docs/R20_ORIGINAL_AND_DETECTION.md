# R20: 원본 예제 인증과 두 감지 후보의 경계

**수업 원본 예제, R10 제출본, R14–R20 연구 실행은 서로 다른 결과다.** R20은 원본 8 kg 예제를 직접 인증하는 도구를 추가하고, 공식 수평 충돌과 연속 충돌에서 남은 실패를 각각 따로 다뤘다. `my_servo.py`, `my_torque.py`, `my_detector.py`는 바꾸지 않았다.

## 수업 원본 8 kg 예제

원본 `run.py --box 8`을 제공 서보 제어기·감지기로 다시 실행했다. 보호한 `sim/`, `model/` 20파일과 실행 파일을 확인한 뒤, 별도 출력 폴더에서 실행했다.

- RMS **6.14 mm**, 최대 오차 **14.00 mm**, 오경보 **7회**
- 생성한 PNG SHA-256은 `82cb22df…e6436c`
- 수업 가이드에 포함된 PNG와 바이트 단위로 일치

이 결과는 R20 연구 제어기를 실행한 결과도, 저장소의 첫 네 비교 MP4를 다시 분석한 결과도 아니다. 원본 키트와 가이드 이미지는 저장소에 복사하지 않는다. [인증 결과](../results/r20/course_example.json)와 [자료 구분](DEMO_SOURCES.md)을 함께 본다.

```bash
KIT=/path/to/original/icpbl_sim
GUIDE=/path/to/IC-PBL_시뮬레이션_실습가이드.html
OUT=/path/to/new-r20-output
mkdir -p "$OUT"

python -B tools/course_example.py \
  --kit "$KIT" --guide "$GUIDE" --out "$OUT/course"
```

도구는 알려진 키트·가이드 해시와 보호 파일을 확인한다. 출력 경로는 존재하지 않는 새 경로여야 한다. 소스 인증과 그래프의 바이트 일치 여부를 따로 기록한다. 그래프가 다르다는 사실만으로 소스 변경이나 렌더러 차이를 단정하지 않는다.

## 원본 공식표에서 세 조합 비교

수업 기본, R10, 단계형 연구 제어·R19 감지 조합을 **수정하지 않은 원본 평가기**에서 비교했다. 표의 검출 수는 숫자 지연으로 구분할 수 있었던 셀만 센다. `경보 중`과 `구분 불가`를 성공으로 바꾸지 않았다.

| 조합 | 서보 검출 | 토크 검출 | 해석 |
|---|---:|---:|---|
| 수업 기본 | 12/24 | 11/24 | 토크는 8셀에서 충돌 전부터 경보 중 |
| R10 제출본 | 23/24 | 18/24 | 공식 무충돌 3조건 오경보 0 |
| 단계형 제어 + R19 연구 감지 | 23/24 | 18/24 | 검출 수 이득 없음 |

단계형 토크 조합의 8 kg 놓기 토크 계단은 **13.1 → 9.4 N·m**, 작업대 힘은 **80 → 82 N**이었다. 놓기 직전 충돌은 15 N 지연이 **91 → 77 ms**로 줄었지만 40 N은 **42 → 45 ms**, 100 N은 **22 → 27 ms**로 느려졌다. 충돌 실행의 최대 오경보 수도 **1 → 2회**였다. 일부 수치가 좋아져도 전체 조합을 승격하지 않은 이유다. [전체 공식표](../results/r20/official_matrix.json)

```bash
python -B tools/r14_grasp_audit.py --kit "$KIT" --out "$OUT/r14-height"
python -B tools/r20_official_compare.py \
  --kit "$KIT" \
  --height-calibration "$OUT/r14-height/calibration.json" \
  --out "$OUT/r20-official.json" --jobs 2
```

## 집기 직후의 수평 15 N

별도 후보는 R10 토크 감지기를 그대로 OR 보존하고, 공개 궤적의 초기 하중 전환 구간(1.35–1.75초)에만 방향 중립 수평 잔차를 추가한다. 정상 20조건의 최대 잔차 **18.015 N**에 2% 여유를 둔 **18.375 N**을 쓴다.

- 공식 토크 검출: **18/24 → 20/24**
- 1.42초, 15 N: 0 kg와 8 kg 모두 `놓침 → 107 ms`
- 같은 위치의 10 N: 둘 다 놓침 유지
- 공식 무충돌 3조건: R10과 후보 모두 오경보 0

한때 22/24였던 해제 구간 확장은 선행 충돌 뒤 정상 잔차를 새 충돌로 오인해 제거했다. 그때 사용한 4조건은 **개발 회귀**이지 독립 검증이 아니다. 최종 후보를 고정한 뒤 새 6조건에서 R10과 후보는 모두 5/6을 같은 지연으로 검출했고 후보만의 추가 검출은 **0건**이었다. 따라서 18→20은 공식 공개 조건의 개선이며 미공개 일반화의 증거가 아니다. [공식표·새 6조건](../results/r20/horizontal.json)

```bash
python -B tools/r20_horizontal_check.py \
  --kit "$KIT" --out "$OUT/horizontal.json"
```

## +41 ms와 +59 ms는 왜 한 충격이었나

4.12 kg의 `i55` 조건은 두 힘의 시작이 **175 ms** 떨어져 있고, 각 힘의 명목 지속시간을 제외한 간격은 **55 ms**다. 둘째 힘 뒤 빠른 물리·예측 경로가 +41 ms, 느린 기존 경로가 +59 ms에 울렸다. 같은 경로의 재발화가 아니라 두 경로의 비동기 인계였다.

처음 만든 넓은 인계는 이를 +41 ms 한 번으로 합쳤지만, 80 ms 간격 조건에서 첫 충격의 잔류 신호를 길게 유지해 실제 둘째 충격의 +24 ms 경보 전 20 ms 무경보 조건을 깼다. 이 후보는 기각했다.

후속 후보는 빠른 경보가 끝나는 순간 느린 증거가 동시에 있을 때만 인계한다. 이 후보는 다음을 함께 보존했다.

- `i55`: 둘째 충격 **+41 ms 한 번**
- 80 ms 간격: 둘째 충격 **+24 ms**, 직전 무경보 유지
- 5.71 kg 기존 조건: **+33 ms** 유지
- 이미 본 18개 네-대조 조건: 기존 통과 항목을 모두 유지하고 엄격 통과 **8 → 9개**

그러나 미리 고정한 새 6조건에서는 R19·넓은 인계·후속 인계가 모두 엄격 **2/6**, 단순히 네 슬롯에 경보가 하나씩 있는 조건은 모두 **3/6**이었다. 두 후보의 새 이득은 없으므로 제출 감지기로 승격하지 않는다. [기존 조건](../results/r20/event_controls.json) · [새 6조건](../results/r20/independent_pairs.json)

새 조건의 사선 힘 두 개는 실제 3축 힘은 맞았지만, 기존 채점기의 배치 벡터 노름과 원본 실행기의 표본별 노름이 1 ULP 달랐다. 원본 계산 순서를 보조 인증하면 세 방식 모두 조건부 **3/6**이지만, 사전 고정한 엄격 점수 **2/6을 대체하지 않는다**. [보조 힘 인증](../results/r20/force_certificate.json) · [실제 적용된 두 사선 힘의 표본 대조](../results/r20/direct_force.json)

이전 18조건 중 사선 성분이 든 3개도 기존의 비트 비교에서는 실패한다. 배포 검사기는 이 실패를 그대로 표시하고, 각 조건을 무충격·첫째만·둘째만·둘 다로 다시 실행한다. 원래 기록을 재현하고 6,000개 전 표본의 시간·3축 힘·힘의 크기가 허용오차 없이 모두 맞을 때에만 다음 단계로 진행한다. 이 추가 검사는 충격 검출 점수를 올리지 않는다. [이전 3조건의 12회 표본 대조](../results/r20/exposed_force_check.json)

```bash
python -B tools/r20_handoff_check.py \
  --kit "$KIT" \
  --height-calibration "$OUT/r14-height/calibration.json" \
  --out "$OUT/r20-handoff.json" --jobs 2
```

## 판정

- **유지:** R10 제출 파일 세 개와 공식 회귀 결과
- **연구 옵션:** 초기 하중 전환의 수평 잔차 후보
- **기각:** 빠른·느린 경로를 넓게 잇는 경보
- **진단 유지:** 느린 경로만 잇는 후속 후보. 기존 조건은 개선했지만 새 6조건 이득 없음

모든 결과는 유한한 CPU 시뮬레이션이다. 실물 로봇 안전, 정지 기능, 비공개 평가 통과, 1 ms 하드 실시간을 보장하지 않는다.
