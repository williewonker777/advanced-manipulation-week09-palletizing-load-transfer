# R7 결과

## 판정

A 서보에는 기록 결함을 고친 검증 경로로 확인한 SCALE_STATE 감지 채널을 채택했고, B 토크는 R1을 유지했다. 재설계는 0회다. S2 실제 대조를 시작한 뒤에는 후보·기록 도구·임계값·관문을 고치거나 실행을 반복하지 않았다.

## 판정 복원 경위

S5 문서 연결 검사 뒤 R1으로 되돌린 기록은 보존했다. 이후 명시적 사용자 결정 ‘서보 후보 채택 복원’에 따라 A 서보 후보를 최종 제출에 복원했다. protocol의 되돌림 조건과 실행 순서에는 문서 연결 검사가 포함되지 않는다. 후보·자료·관문 숫자는 바꾸지 않았고 시뮬레이션·holdout·공식 평가는 다시 실행하지 않았다. 복원한 최종 조립으로 작업 사본 688개와 공개형 사본 569개 전체 테스트, 각 기본 제출 계약 8개를 새로 통과했다. 기존 677개 기록은 S4 후보 계약의 보존값이며 이번 테스트 수와 합치지 않는다.

## 기록 결함과 사전 시험

R6 중단 원인은 비교 결과의 `numpy.bool_`를 표준 JSON encoder가 거부한 것이다. R7은 NumPy bool·정수·실수 scalar만 기본형으로 바꾸는 단일 기록기를 사용한다. 배열, NaN, 무한대, 그밖의 객체, 비문자 key는 오류로 멈춘다. 합성 seed를 쓴 별도 사본에서 대조부터 문서 생성까지 전 구간 기록을 사전 시험했다. 후보로 공식 조건을 미리 실행하지 않았다.

## 동등성과 full-loop 대조

저장 자료 990개(방식별 495개)의 실제 감지기 출력과 새 조건 8회의 물리 8배열을 dtype·shape·바이트 단위로 비교해 모두 같았다.

비교 대상은 `q`, `q_d`, `tau`, `e_mm`, `f_table`, `f_tool`, `qpos`, `r`, packet, 경보, 점수, EMA다. 허용오차 없이 dtype·shape·C-order 바이트를 비교했다.

## 요구사항·평가기 점검

가이드 33개 항목은 24개 충족, 4개 부분 충족, 5개 판정 불가다. 런타임 입력·제출 형식·무결성 8개 검사는 모두 통과했다. 최종 감지 파일이 바뀌어도 허용 입력과 제어기를 바꾸지 않아 이 판정은 유지된다. 상세는 [요구사항 점검](REQUIREMENTS_AUDIT.md)에 있다. 원본 평가기 탓으로 판정이 바뀐 항목은 없다. 공식 8 kg의 R1 놓침 6건 원인은 [이전 감사 요약](../docs/R4_README.md#평가기-점검과-미검출-원인)에 있다.

## 미달

- G4 기준은 마지막 20 ms 평균 ≥50 %mg, 최소 ≥25 %mg, v1 대비 +25 %p, 놓기 힘 ≤1.1 mg다. 현재 A는 평균 0.2098, 최소 0.0000, 증가 0, peak 1.0045; B는 평균 11.1507, 최소 0.3802, 증가 0, peak 1.0140이다.
- 새 holdout 합산 최대 2210.500 µs다. R1 관측 최대 A 11.703 ms, B 14.163 ms와 함께 모든 1 ms 초과 주기를 보존했다.
- 공식 8 kg의 집기 1.42 s 10·15 N과 놓기 3.86 s 10 N에서 현재 미검출은 A 3건, B 3건이다. R1은 두 방식 각 3건, 총 6건이었다.
- 무충돌 섭동 28 reference FA는 A 6→6, B 9→9다.
- D4 R1 A 서보 포화는 2/189다. 후보 채택 여부와 별개로 이 한계를 공개한다.
- 유한 시뮬레이션 결과이며 하드웨어 안전 보장이나 충돌 정지 인증이 아니다.
