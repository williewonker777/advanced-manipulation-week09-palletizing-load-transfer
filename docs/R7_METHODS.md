# R7 방법 — 결과 기록 수정과 재검증

## 범위

R7은 R6에서 멈춘 결과 기록 경로만 고친다. A 서보 후보 파일, 방식별 모델 263개 파라미터, 임계값, 정규화, R1 분기, A·B 제어기, 수치 관문은 바꾸지 않는다. B 토크는 R1을 유지한다. 재설계는 0회다.

## 엄격한 기록기

R6의 full-loop 결과에는 NumPy 비교에서 생긴 `numpy.bool_`가 포함됐다. 표준 JSON encoder는 이 값을 거부했다. R7은 모든 새 JSON 기록을 하나의 기록기로 모은다. 이 기록기는 NumPy bool·정수·실수 scalar만 Python 기본형으로 바꾼다. Python의 기본 dict·list·tuple·문자열·숫자·bool·None은 기존 의미를 유지한다.

NumPy 배열은 0차원 배열도 거부한다. NaN·무한대, 비문자 key, set·bytes·complex·Path·임의 객체도 거부한다. 값을 문자열이나 목록으로 조용히 바꾸지 않는다. 직렬화를 먼저 끝낸 뒤 같은 디렉터리의 임시 파일을 fsync하고 원자적으로 공개한다. 따라서 유형 오류가 최종 이름의 부분 파일을 남기지 않는다.

## 전 구간 사전 시험

실제 R7 조건을 열기 전에 별도 사본과 예약 범위 밖 합성 seed로 다음 순서를 끝까지 시험한다.

1. 후보와 비교 파일의 full-loop 대조를 기록한다.
2. 합성 protocol을 등록하고 후보와 R1 fallback을 동결한다.
3. 합성 holdout을 한 번 열고 설계·실행·검토한다.
4. 공식 기록 경로는 R1으로 원본 평가 경로를 실행해 시험한다. 후보를 공식 조건에서 미리 실행하지 않는다.
5. 공식 회귀, 최종 계약, 판정, 문서와 PDF를 생성하고 다시 검사한다.

실제 Plant와 설치된 NumPy를 쓰며 A 서보·B 토크, 후보·R1, 검출·놓침, 충돌·무충돌을 모두 포함한다. 합성 출력은 실제 판정에 쓰지 않는다. 사전 시험 중 결함을 고치면 새 디렉터리에서 전 구간을 처음부터 다시 통과해야 한다.

## 실제 순서와 멈춤 규칙

사전 시험과 전체 단위 검사·기본 제출 이름 8개 계약이 통과한 뒤 새 질량·seed의 full-loop 8회를 실행한다. A는 후보와 동결 R5 A_STATE, B는 후보와 R1을 비교한다. 물리 8배열, packet, 경보, 점수, EMA를 허용오차 없이 dtype·shape·바이트로 대조한다.

이 대조가 통과한 뒤에만 `PROTOCOL_R7.json`을 커밋한다. 이어 최종 후보와 R1 fallback을 동결·커밋하고, 새 holdout 조건을 한 번만 생성한다. holdout은 1 batch, 공식 평가는 원본 `evaluate.py`와 원본 `sim/`·`model/`로 1 batch만 실행한다. S2 실제 대조를 시작한 뒤 어느 단계든 실패하면 파일을 고치거나 재실행하지 않고 미리 동결한 R1을 선택한다.

## 관문

서보 holdout은 추가 검출 2 이상, R1 검출 손실 0, 도구 접촉 손실 0, 조건별 FA 비증가, 정상 reference FA 0, 물리 8배열 bit 일치, 합산 p99 800 µs 이하를 요구한다. 토크는 R1 경보·물리값 동일성을 요구한다. 최대 1 ms는 목표이며 관문이 아니다. 모든 초과 주기와 최대값을 남긴다.

공식 회귀는 0/4/8 kg 무충돌 FA 0/0/0, 포화 0 %, 비발산, 운반 지연 허용 폭을 요구한다. A는 15 N 50 ms 이하, 10 N 67 ms 이하이고 B는 15 N 48 ms 이하, 10 N 61 ms 이하다. B는 R1과 정확히 같아야 한다.

A 후보가 공식 조건에서 실제로 시험되면 지연, FA, TCP RMS·최대, 포화, 집기·놓기 계단의 54개 지정 셀을 R5 후보 기록과 정확히 비교한다. 계산 시간과 설명 필드는 이 결정론 비교에서 제외한다. R1 fallback이면 후보 결정론 검사는 적용하지 않는다.

## 결과 해석

저장 validation·development·D4·섭동의 990개 신호 스트림 동등성은 과거 결과를 승계할 수 있는 근거다. 새 효능 시험으로 세지 않는다. 새 holdout만 독립 효능 판단에 쓴다. 과거 R5 공식 JSON의 `R3_delay_ms`·`R3_false_alarms`는 이름과 달리 R5 후보 값을 담으므로 원자료를 보존하고, R7 새 결과는 `tested_delay_ms`·`tested_false_alarms`를 쓴다.

공개 결과에는 조립기, 모델, 집계, protocol·동결·판정, 문서 생성기와 검사 도구를 포함한다. 원시 시계열과 취득 드라이버는 포함하지 않는다. 유한 시뮬레이션은 하드웨어 안전 보장이나 충돌 정지 인증이 아니다.
